# 家庭维修报销账本

端口规划：`5114`

```bash
npm install
npm run dev
npm test        # 规则与存档的单元测试（node:test，无需额外依赖）
```

把家庭维修账目做成可核对的流水：实付金额、待收金额、已报销分开统计，互不混淆。

## 账目规则

- 完工时登记**发票号、实付金额、垫付人**，三件套缺一不可。
- 一个发票号同一时间只能挂在一笔维修上，换发票后旧号码才释放。
- **未完工不能报销**；已完工但未登记发票的（含旧版迁移数据）需先补登发票。
- 提交报销先**占用**申请金额（待收）；到账后转为**已报销**；退回必须填原因，撤销无需原因——两者都会恢复可再申请额度，且记录保留。
- 同一笔维修「待收 + 已报销」不超过实付金额；换发票时新实付也不能低于在途与已到账合计。
- 换发票、撤销申请都保留旧记录，报销流水里旧账照常查看。

## 代码结构（规则 / 存档 / 页面分开维护）

- `src/rules.js` —— 账目规则：状态流转与校验，不碰页面和存储，校验失败抛 `LedgerError`。
- `src/store.js` —— 存档：localStorage 读写、数据形状校正、旧版（v1）数据迁移。
- `src/pages.js` —— 页面：渲染与交互，只调用规则层、不做业务校验。
- `tests/` —— 规则、存档与页面渲染的单元测试。

金额一律以“分”存储，避免浮点误差。
